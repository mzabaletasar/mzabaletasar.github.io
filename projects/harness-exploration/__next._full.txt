6:T5e72,<p><em>Note: This post is based on a poster that I will be presenting at the&nbsp;</em><span><em>International Conference on Embodied Cognitive Science (</em></span><em><a href="https://www.oist.jp/conference/ecogs-2026" target="_blank" rel="noreferrer">ECogS</a>) at OIST (Onna, Japan). If you happen to be going there, please reach out!</em></p><p>In this post, I explore how the design of an LLM harness shapes the cognition and behavior of the larger system around a model. I first explain what a harness is, then propose four levels at which these systems can be understood and changed, and finally use a series of experiments to study how simulated cognitive content and changes to the writing process&nbsp;<span>can reduce AI</span><span> </span><em>slop</em><span>.</span></p><details class="article-toc" open=""><summary>Table of Contents</summary><ul><li><a href="#what-is-a-harness">What is a harness?</a></li><li><a href="#harness-design-and-cognitive-architectures">Harness design and cognitive architectures</a><ul><li><a href="#four-levels-of-harness-design">Four levels of harness design</a></li></ul></li><li><a href="#the-quest-to-reduce-ai-slop">The quest to reduce AI <em>slop</em></a><ul><li><a href="#providing-cognitive-context-and-inspiration">Providing cognitive context and inspiration</a></li><li><a href="#a-richer-cognitive-architecture">A richer cognitive architecture</a></li></ul></li><li><a href="#discussion">Discussion</a></li><li><a href="#references">References</a></li><li><a href="#appendix-cognitive-prompts">Appendix</a></li></ul></details><h2 id="what-is-a-harness">What is a harness? Intuition and Motivation</h2><p>An LLM harness is the code that is built around an LLM to make it agentic&nbsp;<span>(run code and operate on your devices, essentially). The latest AI systems (ChatGPT desktop, Claude Code, Openclaw, etc) all have their own harness, specifically tailored to make the greater system behave in the way they intend. Here is a simplified&nbsp;</span>schematic<span>&nbsp;of how these systems work:</span></p><figure class="article-inline-figure" id="figure-1"><a href="/images/harness-exploration/harness-architecture.svg?v=9" target="_blank" rel="noreferrer"><img src="/images/harness-exploration/harness-architecture.svg?v=9" alt="Two diagrams of an LLM harness. The first shows an LLM connected to tool calls, Markdown files, memory, and a sandboxed code runtime. The second shows the harness reading AGENTS.md, available tool definitions, and recent memory before passing their outputs with the request to the LLM; the LLM selects a sandboxed Python tool call, receives its output, crafts a response, and updates memory." width="815" height="1245"></a><figcaption class="article-figure-caption">Figure 1. Top: high-level view of the harness as a system around the model. Bottom: an example of what one concrete user request would look like.</figcaption></figure><p>At a high level, the LLM is connected to a set of files for instructions and preferences, scripts for tool calls, and some sort of memory module that is refined as the user interacts. When the user asks for something (as in the example below), the LLM will typically first read the <em>AGENTS.md</em>&nbsp;file for instructions, then have a high-level view of the tools it has access to, and based on that execute whatever tools it thinks are needed to complete the request.&nbsp;</p><p>This framework might look simple at first, but it is incredibly flexible and powerful. We can build agents that <a href="https://docs.openclaw.ai/start/showcase" target="_blank" rel="noreferrer">control devices around the house through conversation</a>, <a href="https://openai.com/index/introducing-chatgpt-agent/" target="_blank" rel="noreferrer">navigate websites and buy things for you</a>, or <a href="https://hermes-agent.nousresearch.com/docs/" target="_blank" rel="noreferrer">remember your preferences and learn how to do tasks over time</a>.</p><p><span>Now, if we think about the behavior of the system, its tendencies, how it responds to us, what it's able to do, how it </span><em>feels</em><span>&nbsp;to interact with it... all of this is in large part determined by the harness. Today the most popular examples of LLM harnesses are quite similar because these projects all have a common vision in mind (broadly speaking, a helpful assistant that can do things for you on software devices).</span></p><p>But what if, instead, you wanted a system that felt genuinely empathetic, funny, or curious? What files should it be connected to, and how should they be organized? Is there something other than <em>.md</em> files that would be a better "medium" for it to interact with? And how do these design choices differ depending on the LLM underneath?&nbsp;</p><figure id="figure-2"><a href="/images/harness-exploration/diversity-of-ai-minds-v1.png" target="_blank" rel="noreferrer"><img src="/images/harness-exploration/diversity-of-ai-minds-v1.png" alt="A shared language model branches through four different interconnected harness configurations into compassionate, humorous, curious, and melancholic characters." width="1672" height="941"></a><figcaption class="article-figure-caption">Figure 2. The same underlying LLM paired with different harnesses can produce systems that feel and behave very differently (in this case compassionate, funny, curious, or reflexive).</figcaption></figure><p><span>We don't know the answers to these questions yet.&nbsp;</span></p><p><span>If we want to </span><span>build a <strong>diverse ecosystem</strong> of AI agents, where everyone can have an agent that feels special to them and that they can benefit from as much as possible</span><span>, it's very important that we improve our understanding of harness design and how it influences the kind of system that you get.</span></p><h2 id="harness-design-and-cognitive-architectures">Harness Design and Cognitive Architectures</h2><p>As we've seen, the harness is a hugely important aspect of an agentic system. It determines what information enters the LLM, how that information is processed, what computation happens along the way, and how the answer is presented to the user.</p><p>I think an appropriate analogy is to treat the harness as the <em>cognitive architecture</em> behind the larger agentic system. That is, making changes in the harness means changing the cognition of the agent. <span class="hover-note"><sup class="hover-note-marker" tabindex="0" aria-label="Show note 1">[1*]</sup><span class="hover-note-card" role="note">I want to note that I am still a novice on this topic and by no means an expert on cognitive science. I am using these terms somewhat loosely, I did however find them fitting when working on this project.</span></span></p><p>I was pretty happy to see that research has already framed artificial cognition in similar terms. Embodied-AI research has treated cognition as arising from the organization of the agent and its interaction with an environment, rather than from its internal controller alone <span class="inline-citation">[<a href="#reference-1">1</a>]</span>. More recently, I found examples like CoALA, which explicitly describes an agent as a cognitive architecture made up of modular memory, actions, and a decision-making process <span class="inline-citation">[<a href="#reference-2">2</a>]</span>. These papers don't use the word <em>harness</em>, but they describe essentially the same concept: a computational architecture that determines the flow of information and behavior of the larger system.</p><p><span>Thinking about harnesses in this way helps us ask what agency and embodiment actually mean in these systems. It also gives us a useful way to organize the design space. If changing the harness means changing the cognition of the larger system, what exactly can we change? I find it useful to separate the possibilities into four levels.</span></p><h3 id="four-levels-of-harness-design">Four levels of harness design</h3><p>Let's take the conventional helpful assistant and imagine we want to make an agent that <strong>surprises</strong> us.<span>&nbsp;</span></p><p>First, we can change the prompts in the usual <em>AGENTS.md</em> or <em>SKILLS.md</em> files. We could construct templates using instructions and examples that make the agent better at surprising us. This is the first level, the <strong>substantial or instantiational</strong>.</p><p>If we think outside of that, however, there's no reason why those have to be the most appropriate files to have. We could instead have a <em>NOVELTY</em><em>.md</em> file that the agent will use to reflect on what novel things the user could appreciate and decide how to proceed based on that. I refer to this level as the <strong>conceptual</strong>.&nbsp;</p><p>Perhaps that's a more effective strategy, but even here, the way in which the LLM interacts with the information is the same: it's just reading <em>.md</em> files that are added to its context. A more creative solution could involve changing the procedure itself. For example, the harness could retrieve recent logs, encode them as points in an embedding space, and interpolate or extrapolate between them to find a candidate that is novel but still close enough to the user's interests. It could then decode that point and pass the result to the LLM. This level of design tackles how information is processed, the <strong>procedural or algorithmic </strong>level.</p><p>Finally, we could imagine multiple agents interacting together. One agent could generate candidate surprises, another could judge whether they fit the user's interests, and a third could decide when to surface them. This is the fourth level, the <strong>topological</strong>: how agents and systems are connected to each other.</p><figure class="article-inline-figure" id="figure-3"><a href="/images/harness-exploration/four-levels-of-harness-design-v2.png" target="_blank" rel="noreferrer"><img src="/images/harness-exploration/four-levels-of-harness-design-v2.png" alt="A harness diagram color-coded across substantial, conceptual, procedural, and topological levels. The left panel shows concrete files and settings inside functional modules around a model. The right panel expands an Embed and Discover module into a procedure that retrieves memory, embeds it, finds a novel candidate, decodes it, and sends it to the model." width="1536" height="1024"></a><figcaption class="article-figure-caption">Figure 3. Four levels of harness design.</figcaption></figure><p><a href="#figure-3">Figure 3</a> illustrates how these levels can appear together within a single harness. To be more specific, I propose these 4 levels:</p><ul><li><strong>Level 1: Substantial or instantiational.</strong> The concrete prompts, parameters, thresholds, or other settings used to instantiate the system.</li><li><strong>Level 2: Conceptual.</strong> The functional objects those elements create (soul, tools, instructions, memories...).</li><li><strong>Level 3: Procedural or algorithmic.</strong> How and when those objects are processed, combined, and added to the flow of information.</li><li><strong>Level 4: Topological.</strong> How the system connects to other agents, external systems, etc.</li></ul><p>I like this framework because it's intuitive and useful for both analyzing existing harnesses and thinking of new approaches. Next, I use it to make sense of a set of preliminary (but promising) experiments with different harness designs.</p><h2 id="the-quest-to-reduce-ai-slop">The quest to reduce AI <em>slop</em></h2><p>I wanted to tackle a problem different from the main use cases people focus on, like recursive self-improvement or computer use. Something harder to measure, but still relevant and manageable in terms of compute. I thought of reducing <em>slop</em>,&nbsp;since it is one of the things that LLMs are characteristically bad at. <span class="hover-note"><sup class="hover-note-marker" tabindex="0" aria-label="Show note 2">[2*]</sup><span class="hover-note-card" role="note">It's very easy to spot <em>slop</em> when you see it. The em-dashes, the "it's not Y, it's X" pattern, the verbosity, and the overuse of technical words are some of the main tells.</span></span></p><p>Turns out there is a benchmark that measures this, the <a href="https://eqbench.com/slop-score.html" target="_blank" rel="noreferrer"><strong>EQ <em>Slop</em> Benchmark</strong></a> <span class="inline-citation">[<a href="#reference-3">3</a>]</span>. So now I can take a model, measure baseline performance, and study how different cognitive architectures improve the <em>slop</em> scores (or not).</p><p>Throughout the project, I am running the <a href="https://huggingface.co/google/gemma-4-26B-A4B-it" target="_blank" rel="noreferrer"><strong>Gemma4-26B</strong></a> model, at temperature 1.0, thinking off, and 5 seeds for robustness. The evaluations are done on<span>&nbsp;</span><span>a subset of 30 writing prompts from the benchmark.&nbsp;</span><span>The baseline (using the default prompt) of this model sits at&nbsp;</span><span><strong>60.83</strong> ± 2.78</span><span>&nbsp;(the lower the better).</span></p><h3 id="providing-cognitive-context-and-inspiration">Providing cognitive context and inspiration</h3><p>My general approach with this project was to take inspiration from humans and see if integrating elements of human cognition into the agent would make it write more like a person. The first experiment came from observing that, when we write, we are partly influenced by the baggage of experience we accumulate as we go through life. So I began by giving the model a simple simulated emotional experience.</p><p>To do this, I placed the model in one of five events, then sequentially asked it for thoughts, feelings, and reflections (I call this the&nbsp;<em>cognitive context</em>). The events range from seeing a fatal car crash to watching a family reunite after a long time. For the exact prompts, see the <a href="#appendix-cognitive-prompts">Appendix</a>.</p><p>We find that providing cognitive context reduces the average <em>slop</em> score, at&nbsp;55.04&nbsp;(p &lt; 0.001) on average, a 9.5% improvement from the baseline.&nbsp;</p><p><span>Another element present in human writing that agents don't explicitly have is that when we see a writing prompt, we get some form of&nbsp;<em>inspiration</em> by thinking about what we want to write about before we write. This is what I tested next</span><span>. In a separate call, I ask what the model draws on from the writing query (either on its own or preceding it with the cognitive context). That output is then passed back into the harness before the model writes the actual response.</span></p><p>Compared to baseline, inspiration improves the score by 6.6% on its own, while combining inspiration with cognitive context improves it by <strong>15.2%</strong> (<a href="#figure-4">Figure 4</a>). The two interventions seem to complement rather than interfere with each other.</p><figure class="article-inline-figure" id="figure-4"><a href="/images/harness-exploration/onepass-content-comparison.png" target="_blank" rel="noreferrer"><img src="/images/harness-exploration/onepass-content-comparison.png" alt="One-pass SLOP scores for cognitive context, inspiration, and both conditions, compared with the Gemma 4 26B thinking-off baseline. Error bars show 95 percent confidence intervals and asterisks show significance against baseline." width="1400" height="760"></a><figcaption class="article-figure-caption">Figure 4. One-pass comparison of cognitive context, inspiration, and both.</figcaption></figure><h3 id="a-richer-cognitive-architecture">A richer cognitive architecture</h3><p>Lastly, I wondered if a richer, more involved cognitive architecture would result in better writing. This time I changed the&nbsp;<span>procedural level of the harness, in the&nbsp;</span><span>way the writing is done</span><span>. By default, LLMs write in one shot, whereas humans write a piece, see how they like it, go back and refine it, etc.</span><span>&nbsp;In these experiments, the LLM would question whether the latest passage was clear and simple and, if it was not, rewrite it before continuing. I experimented with revising every 1, 10, and 20 sentences.</span></p><figure class="article-inline-figure" id="figure-5"><a href="/images/harness-exploration/ecogs-factorial-results.png" target="_blank" rel="noreferrer"><img src="/images/harness-exploration/ecogs-factorial-results.png" alt="SLOP scores across one-pass generation and revision every 20, 10, or 1 sentence, comparing no added content, cognitive context, inspiration, and context plus inspiration. Error bars show 95 percent confidence intervals." width="1400" height="760"></a><figcaption class="article-figure-caption">Figure 5. Full factorial comparison of cognitive context, inspiration, and self-monitoring interval.</figcaption></figure><p>As shown in <a href="#figure-5">Figure 5</a>, when the system has neither cognitive context nor inspiration, changing the writing procedure doesn't significantly improve the <em>slop</em> score at the 10- or 20-sentence intervals. Revising after every sentence actually makes it significantly worse. But once cognitive context and inspiration are included, the same procedure produces much larger gains: <strong>26.9%</strong> when revising every 10 sentences and <strong>27.4%</strong> every 20.</p><p>The factorial comparison allows us to isolate the effects of different interventions and identify when the interactions between them are important. Looking at the procedural intervention with no context or inspiration (blue line), one could conclude that changing the writing regime in this way is not effective. However, once cognitive context or inspiration are included, the same change in writing regime produces much larger gains.</p><p><span>We also see that the ordering of the content conditions is maintained across every writing regime. The version with neither cognitive context nor inspiration is always the worst, either one alone is better, and both together are always best. This is still one model and one benchmark, so I would not call the result robust in a broad sense. But it does suggest that the benefit of the added content is stable across the writing procedures tested here, and points to the fact that it is possible to find modifications in cognitive architectures that result in persistent, cohesive changes in behavior.</span></p><h2 id="discussion">Discussion</h2><p>I think there is an interesting connection to cognitive science here. The three interventions loosely correspond to what a system carries from the past, how it is oriented toward a task, and how it interacts with an environment as it acts. Here, that environment is just the text it has already written, which it repeatedly reads, evaluates, and changes. This obviously does not make the system embodied in any strong sense. But it gives us a simple case for asking when apparent cognitive functions become useful because of how they are organized within a larger process. These results suggest that achieving a desired behavior may require us to explore the design of cognitive architectures holistically across the four levels.</p><p>These experiments have obvious limitations (one model, one benchmark, etc.). Still, I think they provide a useful example of how one might explore AI cognition and make sense of the design space using the four-level framework.</p><p>This technology is already impressive, is advancing quickly, and will likely become an increasingly important part of our lives. But we still have many fundamental and fascinating questions to answer, including ones that examine the nature and limits of embodied cognition. Ultimately, how can harness design shape the cognition of an AI agent, and how can we use this knowledge to create agents that are genuinely beneficial and feel special to people?</p><hr class="article-divider">
